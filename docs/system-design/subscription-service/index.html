Where the hard parts are​

Recurring billing is where payment failure modes concentrate. Read these before changing any state transition:

  • Payment state and idempotency — a payment is a state machine with an idempotency key, never a boolean.
  • Payment provider and webhooks — a provider response and a webhook are external signals, not truth.
  • Order and payment consistency — money moved and the subscription updated are two facts in two places, and no transaction spans both.
  • Refunds — a refund is a new transaction, not an undo. Mid-cycle cancellation is a refund question.
  • Temporal data — a price or plan that changes over time means the billing decision must be defensible after the fact.
